about=QGIS Environment Manager looks after the environment around QGIS. Diagnostics: version, release line (LTR or latest), Python, Qt, how QGIS was installed (on Linux: official repository, Flatpak, Snap, distribution), warnings such as an older-than-LTR version or the QGIS repository signing key that expires on 2027-08-08, and a report you can copy for support. Plugins and QGIS 4: reads each installed plugin's metadata.txt and shows what it declares for QGIS 3 and QGIS 4 (supportsQt6, minimum and maximum QGIS version), so you know what to check before moving to QGIS 4. Requirements: the GIS GEORGIA plugins that need system tools (PostgreSQL client tools and psycopg2 for PostGIS Manager, ExifTool for Photo Geotagger, SAGA and GRASS for GeoEco) are checked, and on Linux the missing ones can be installed with your package manager after you review the exact commands. Components: the programs and libraries around QGIS (GDAL, PROJ, GRASS, SAGA, Python libraries such as NumPy, pandas, Shapely, rasterio, database clients) with what is installed and what can be added, installed with your package manager after you review the commands - the small Linux form of the OSGeo4W chooser. Doctor (Diagnostics tab): looks for what is known to break QGIS, through the Python that QGIS itself runs - your own copy of a Python library hiding the system one, GDAL tools and GDAL for Python of different versions, a bad PROJ path, a QGIS repository of another release, a half-finished package database, no free disk - and says what it could not look at. Environment file: write down which QGIS and which components a machine has and make other machines match (a class room, an office); the file holds only names from closed lists, never commands, and is checked before anything else. Safety: before anything is installed or changed the package manager is asked, in its own simulation mode, what it would do (how many packages, how much to download, whether something would be removed) and the answer is shown with the commands; before QGIS is changed in place a zip copy of your profile is made (only if that works), a copy can be restored as a new profile without touching the one in use, an installation can be taken back to another version the repositories offer, and a version can be kept so that updates skip it. Installed QGIS programs: every QGIS on the machine (system packages, Flatpak stable and lts, containers, Snap) with its version, a read-only check whether a newer build is waiting, and a way to start the one you pick after you see the command. QGIS versions: update the QGIS you have, or install another one next to it (Flatpak stable or lts, containers) or in its place - the program recommends the best way for your system and says why, shows every command first, and asks twice before changing the QGIS you are using right now; a zip copy of your profile can be made first. The logic is shared with the standalone qgis-installer (https://github.com/kapo-Toolkits/linux-scripts).
